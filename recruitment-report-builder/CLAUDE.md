# CLAUDE.md｜recruitment-report-builder 開発ルール

## プロジェクトの目的

求人媒体の結果データから、KPI集計・分析サマリー・PowerPoint報告資料を半自動作成する
**汎用・セルフ実装型のClaude Skill**を作る。複数企業で利用でき、初回に対話で会社別設定を作成する。
実在企業データは使わず、架空デモデータで完成形を作る。

## ディレクトリ構成

```text
recruitment-report-builder/
├── CLAUDE.md / README.md / SKILL.md
├── agents/        # エージェント定義
├── references/    # Skillが参照する詳細ルール（分析・文章・KPI・検証など）
├── templates/     # 会社別設定テンプレート（YAML/CSV）
├── demo/          # 架空デモデータ・正解データ
├── assets/        # 空のPPTXテンプレート
├── scripts/       # Pythonスクリプト（数値処理はすべてここ）
├── tests/         # pytest
├── output/        # 生成物置き場（コミットしない・上書きしない）
└── docs/          # 設計書・マニュアル
```

## 数値計算に関するルール（最重要）

- 数値計算は必ず `scripts/` のPythonスクリプトで行う。**生成AIの文章推論で数値を計算・補完しない。**
- 元データにない情報を補完しない。空欄（欠損）と0を区別し、空欄を0に変換しない。
- 0除算は0を返さず「算出不可（N/A）」。前月なしは「NEW」、目標なしは「NOT_SET」。
- 率・単価の集計値は合計値から再計算する（明細の率の平均を取らない）。
- PowerPoint内の数値は計算済みCSVからのみ取得する。手入力禁止。
- エラーや欠損を隠さない。検出したものはすべて報告する。

## コーディング規約

- Python 3.10以上。pandas / openpyxl / python-pptx / PyYAML / pytest を使用。
- 各スクリプトはCLI実行可能（argparse）。入出力パスは引数で渡す。ハードコードしたパス禁止。
- エラーメッセージ・ログは日本語で分かりやすく（対処方法を含める）。
- 関数に型ヒントを付ける。1スクリプト1責務。
- ログは標準出力+ファイル（`output/` 配下）へ出力。

## ファイル命名規則

- スクリプト: `snake_case.py`、テスト: `tests/test_<対象>.py`
- 出力: `output/YYYY-MM/<種別>_<期間>.csv` 等。同名存在時は連番付与し上書きしない。
- 設定バックアップ: `<元名>.bak-<YYYYMMDD-HHMMSS>`
- ドキュメント: `kebab-case.md`

## テスト実行ルール

- 実行コマンド: `python -m pytest tests/ -v`（リポジトリの `recruitment-report-builder/` 直下で実行）
- デモデータ（`demo/`）と正解データ（`demo/expected-kpi-results.csv`）を突き合わせる。
- 浮動小数点比較は許容誤差付き（率±0.05pt、単価±0.5円。フェーズ3で確定）。
- スクリプトを変更したら関連テストを実行し、結果（成功/失敗数）をそのまま報告する。

## PowerPoint生成時のルール

- 白背景・ビジネス向け・1スライド1メッセージ・数字を大きく。
- N/Aは「算出不可」、前月なしは「新規」、目標なしは「未設定」と表示。0と表示しない。
- グラフと表の数値を一致させる。テーマ色は1箇所（設定）で定義し差し替え可能にする。
- 実在企業のロゴ・商標を使用しない。
- 生成後にファイルが開けること・数値がCSVと一致することを検証する。

## 機密情報を扱う際の注意

- 実在企業・実在人物の情報をコード・デモ・ログ・コミットへ含めない。
- 個人情報らしき列（氏名・電話・メール等）を検出したら警告し、処理を進めない。
- 設定ファイルへ認証情報（媒体のID/パスワード等）を保存しない。

## フェーズごとに停止するルール

- 指示されたフェーズだけを実行し、完了条件を満たしたら**停止**する。
- 一度に複数フェーズを実行しない。次フェーズへは人の確認後に進む。
- 完了時に報告する: 作成ファイル一覧 / テスト結果 / 仮定した内容 / 未確定事項 / 次フェーズ予定。
- 未確定事項は勝手に決めず `docs/open-questions.md` へ記録する。
- 既存ファイルを変更する前にバックアップを取る。
