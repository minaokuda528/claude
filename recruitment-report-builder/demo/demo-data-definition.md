# デモデータ定義書

すべて架空データです。実在の企業・人物・実績とは無関係です。
架空企業: 株式会社サンプル採用企画（`demo-company-settings.yaml`）

- 当月: 2026-06（`demo-current-month.csv`）— 明細9行 + 合計1行
- 前月: 2026-05（`demo-previous-month.csv`）— 明細8行
- 目標: `demo-targets.csv` — 7行（2求人分を意図的に未設定）
- 媒体: Indeed / 求人ボックス / エンゲージ、職種: 法人営業 / 一般事務 / コールセンタースタッフ、拠点: 東京 / 大阪

## 意図的に仕込んだケース対応表

| # | 指定ケース | 該当データ |
|---|---|---|
| 1 | 応募数が増加した媒体 | Indeed 法人営業 東京（20→30件、CPAも5000→4000円へ改善） |
| 2 | 応募数は増えたが応募単価が悪化 | Indeed 一般事務 東京（25→30件、CPA 3000→5000円） |
| 3 | クリック数は多いが応募率が低い | 求人ボックス 法人営業 大阪（クリック1500、応募率0.3%） |
| 4 | 応募数は少ないが採用率が高い | エンゲージ 一般事務 大阪（応募4件、採用率50.0%） |
| 5 | 新規掲載で前月データがない | エンゲージ コールセンタースタッフ 東京（前月CSVに行なし → NEW） |
| 6 | 応募数が0件 | 求人ボックス 一般事務 東京（応募0 → CPA算出不可） |
| 7 | 採用数が0件 | 求人ボックス 法人営業 大阪 ほか（採用単価N/A） |
| 8 | 空欄があるデータ | Indeed コールセンタースタッフ 大阪（表示数・面接数が空欄。0ではなく欠損） |
| 9 | 媒体名の表記揺れ | 「indeed」（小文字）、「求人BOX」→ 正式名称へ統一対象 |
| 10 | 数値形式の不統一 | 「22,000」「120,000円」「150000円」などカンマ・円混在 |
| 11 | 合計値と明細値の不一致 | 当月CSVの合計行: 応募数103（明細合計は98。+5のずれ） |
| 12 | 異常に高い応募単価 | 求人ボックス コールセンタースタッフ 大阪（CPA 80,000円 > 警告閾値50,000円） |
| 13 | 広告費が0円 | エンゲージ 法人営業 東京（費用0円で応募6件 → 要確認警告） |
| 14 | 目標値が未設定 | ケース5の新規求人 と 求人ボックス コールセンタースタッフ 大阪 |

追加の揺れ: 列名が当月と前月で異なる（媒体名/媒体、勤務地/拠点、表示回数/表示数、広告費用/広告費）、
職種名の先頭に全角空白（当月 エンゲージ「 コールセンタースタッフ」）。

## 正解データ

- `expected-kpi-results.csv`: 明細9行 + 全体合計1行。`generate_expected_kpi.py` がスクリプト計算で生成。
- `kpi-calculation-process.md`: 全行の計算過程（自動出力）。
- 特殊値: `N/A`=算出不可 / `NEW`=前月なし / `NOT_SET`=目標未設定。
- 前月比・目標比は「応募数」「応募単価」の2軸で収録（仮定。他KPIの比較はフェーズ3以降で拡張可能）。
- 広告費0円の行は単価を数値0で保持し、警告フラグで「費用0円（要確認）」表示に変換する設計。

再生成方法: `python3 demo/generate_expected_kpi.py`
