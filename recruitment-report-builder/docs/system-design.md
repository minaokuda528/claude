# システム設計書｜recruitment-report-builder

- 版数: 1.0（フェーズ1）
- 前提: `docs/requirements.md` に基づく

---

## 1. 全体構成

Claude Skill（対話・分析・文章生成）+ Pythonスクリプト（数値処理）のハイブリッド構成。

- **Claudeが担当**: 利用者との対話、設定作成、ファイル形式判定の補助、サマリー文章の作成（構造化JSONを根拠として）、資料内容の説明
- **スクリプトが担当**: 正規化、KPI計算、検証、PowerPoint生成 — **すべての数値処理**

```text
入力(CSV/Excel) → normalize_data.py → validate_data.py →(エラーなら停止)
  → calculate_kpi.py → generate_summary_input.py → [Claudeがサマリー作成]
  →(人による確認)→ generate_pptx.py → 最終検証 → 納品物
```

オーケストレーションとして `run_report.py` が上記を順に実行する（フェーズ3以降で実装）。

## 3. 入出力仕様

### 3.1 入力

| ファイル | 形式 | 必須 | 内容 |
|---|---|---|---|
| 当月データ | CSV/xlsx | 必須 | 媒体×職種×拠点の実績行 |
| 前月データ | CSV/xlsx | 任意 | 同上（前月分） |
| 目標値 | CSV/xlsx | 任意 | 媒体または求人単位の目標 |
| 会社設定 | YAML | 必須 | `company-settings.yaml`（初回設定で生成） |
| 媒体マッピング | CSV | 必須 | 媒体名・列名の表記揺れ対応表 |
| 補足コメント | テキスト | 任意 | 背景情報 |

文字コードはUTF-8(BOM可)とShift_JISを自動判定する。

### 3.2 出力（すべて `output/YYYY-MM/` 配下、タイムスタンプ付き）

| ファイル | 生成元 |
|---|---|
| `normalized_<期間>.csv` | normalize_data.py |
| `validation_report_<期間>.csv` / `.md` | validate_data.py |
| `kpi_results_<期間>.csv` | calculate_kpi.py |
| `summary_input_<期間>.json` | generate_summary_input.py |
| `summary_<期間>.md` | Claude（ルールに基づく） |
| `report_<会社名>_<期間>.pptx` | generate_pptx.py |
| `run_log_<日時>.log` | 各スクリプト共通ログ |

## 4. 標準データモデル

`docs/requirements.md` §6 の標準項目を正とする。集計キーは `(media, job_category, location, period)`。

集計階層:

1. 明細（媒体×職種×拠点）
2. 媒体別合計
3. 職種別合計
4. 拠点別合計
5. 全体合計

率・単価は**合計値から再計算**する（明細の率の平均を取らない）。

## 5. KPI定義（正）

表記: 率 = %表示・小数1桁 / 単価 = 円・整数四捨五入 / 比率 = %表示・小数1桁

| # | KPI | 内部キー | 計算式 | 必要項目 | 分母0 | 分子または分母が欠損 |
|---|---|---|---|---|---|---|
| 1 | 表示数 | impressions | 実数（合計） | impressions | — | 欠損のまま（0にしない） |
| 2 | クリック数 | clicks | 実数（合計） | clicks | — | 同上 |
| 3 | 応募数 | applications | 実数（合計） | applications | — | 必須項目のため欠損はエラー |
| 4 | 面接数 | interviews | 実数（合計） | interviews | — | 欠損のまま |
| 5 | 採用数 | hires | 実数（合計） | hires | — | 欠損のまま |
| 6 | 広告費 | cost | 実数（合計） | cost | — | 必須項目のため欠損はエラー |
| 7 | クリック率 | ctr | clicks / impressions | 両方 | N/A（算出不可） | N/A |
| 8 | 応募率 | application_rate | applications / clicks | 両方 | N/A | N/A |
| 9 | 面接設定率 | interview_rate | interviews / applications | 両方 | N/A | N/A |
| 10 | 採用率 | hire_rate | hires / applications | 両方 | N/A | N/A |
| 11 | クリック単価 | cpc | cost / clicks | 両方 | N/A | N/A |
| 12 | 応募単価 | cpa | cost / applications | 両方 | N/A | N/A |
| 13 | 採用単価 | cph | cost / hires | 両方 | N/A | N/A |

比較指標:

| 指標 | 計算式 | 特殊ケース |
|---|---|---|
| 前月比（増減率） | (当月 − 前月) / 前月 | 前月データなし → `NEW`（新規/比較不可）。前月=0かつ当月>0 → `N/A`（比率算出不可、差分は表示可）。両方0 → 0% |
| 目標比（達成率） | 当月 / 目標 | 目標なし → `NOT_SET`（未設定）。目標=0 → `N/A` |

特殊値の内部表現（CSV上）:

- `N/A` = 算出不可（0除算・欠損）
- `NEW` = 前月データなし
- `NOT_SET` = 目標未設定

PowerPoint表示: `N/A`→「算出不可」、`NEW`→「新規」、`NOT_SET`→「未設定」。**0と表示しない。**

## 6. 分析ルール（概要。詳細はフェーズ4）

- 出力は「事実」「示唆」「要確認」の3区分に必ず分ける。
- すべての記述に根拠数値（KPI結果CSVの値）を付ける。
- 好調/注意/改善優先の判定閾値は会社設定で定義（デフォルト値を用意）:
  - 好調: 目標比 ≥ 100% または 応募数前月比 ≥ +20%（仮のデフォルト）
  - 注意: 応募単価が目標比 ≥ 120% または 応募数前月比 ≤ −20%（仮のデフォルト)
- 応募数のみで媒体を評価せず、単価・率と併せて記述する。
- 採用数がない場合、費用対効果を断定しない。

## 7. 例外処理設計

### 区分

| 区分 | 動作 | 例 |
|---|---|---|
| エラー | 処理停止。確定資料を作らない | 必須列不足、数値以外、マイナス値、面接数>応募数、採用数>面接数、合計不一致 |
| 警告 | 続行するがレポートへ明記 | 前月なし、目標なし、未登録媒体、異常値、重複疑い、費用0円で応募あり、空欄 |

### エラーコード体系（案）

- `E-xxx` = エラー、`W-xxx` = 警告
- 例: `E-001 必須列不足`, `E-010 面接数が応募数を超過`, `W-001 前月データなし`, `W-010 応募単価が閾値超過`

各検出結果は「行番号・対象・内容・対処方法（日本語）」を含む。

## 8. PowerPoint構成（10スライド）

| # | スライド | 主な内容 | データソース |
|---|---|---|---|
| 1 | 表紙 | 資料名・対象期間・会社名・作成日 | 会社設定 |
| 2 | エグゼクティブサマリー | 全体結果・主要変化3点・要確認 | サマリーMD |
| 3 | 主要KPI | 全体合計KPIを大きく表示。前月比・目標比 | KPI結果CSV |
| 4 | 媒体別比較 | 媒体別KPI表 + 応募数/応募単価グラフ | KPI結果CSV |
| 5 | 職種別比較 | 職種別KPI表 + グラフ | KPI結果CSV |
| 6 | 拠点別比較 | 拠点別KPI表 + グラフ | KPI結果CSV |
| 7 | 好調求人・要改善求人 | 判定ルールによる上位/下位求人 | KPI結果CSV + 判定 |
| 8 | 課題分析 | 事実と示唆（区分明示） | サマリーMD |
| 9 | 次月の改善案 | 優先度付き改善案 | サマリーMD |
| 10 | 要確認事項 | 人が判断すべき項目・データ警告 | サマリーMD + 検証結果 |

デザイン: 白背景・ビジネス向け・1スライド1メッセージ・数字を大きく。
ブランドカラーとロゴは会社設定から差し替え可能な設計（テーマ色を1箇所で定義）。
数値はすべて計算済みCSVから取得し、手入力・文章推論での埋め込みを禁止する。

## 9. 初回設定フロー（セルフ実装）

1. Skill起動 → 会社設定ファイルの有無を確認
2. なければ初期設定モードへ案内
3. 質問を5〜8問ずつ段階提示（基本情報 → 媒体設定 → 目標設定 → 資料設定 → 分析設定）
4. 「不明」「未設定」を許容し、後から変更可能と案内
5. 回答の矛盾を検出（例: 必須KPIに採用単価があるのに採用数列がない）
6. 設定内容の確認画面を提示
7. 利用者の承認後に `company-settings.yaml` / `media-mapping.csv` / `report-settings.yaml` を確定

## 10. 通常利用フロー（月次）

1. 利用者が当月データ（+前月・目標）を渡す
2. 会社設定を読み込み、ファイル形式・必須項目を確認
3. 不足情報だけを質問
4. 標準化 → 検証（エラーなら停止・報告）→ KPI計算
5. サマリー入力JSONを生成し、Claudeがサマリー作成
6. **人がサマリーを確認・承認**
7. PowerPoint生成 → 最終検証
8. 完成ファイル・要確認事項・警告一覧を提示

## 11. 検証モード / 設定変更モード

- **検証モード**: 手順1〜4のみ。KPI結果と検証レポートを提示し、PPTXを作らない。
- **設定変更モード**: 既存YAMLをバックアップ後、変更点だけを対話で確認して更新。

## 12. 技術方針

- Python 3.10以上
- ライブラリ: pandas, openpyxl, python-pptx, PyYAML, pytest（`requirements.txt` はフェーズ3で作成）
- 全スクリプトはCLI実行可能（argparse）、入出力パスは引数指定、日本語エラーメッセージ、ログ出力
- 浮動小数点比較の許容誤差: 率±0.05ポイント、単価±0.5円（仮。フェーズ3で確定）
- 元ファイルの上書き禁止。既存ファイル変更時は `.bak` バックアップ
