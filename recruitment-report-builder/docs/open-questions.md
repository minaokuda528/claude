## フェーズ8 統合テスト結果と残存制限

10シナリオ + 再現性・元データ保護・出力・ログを `tests/test_integration.py` で検証（全46テスト成功）。

修正した不具合:
- **E-001 vs E-002 の取り違え**: 標準化後は必須列が常に存在（空で補完）するため、
  応募数・広告費の列が丸ごと無いケースが E-002（空欄）として出ていた。
  「必須列が1件も値を持たない」を E-001 として検出するよう修正（両者ともレポートは停止）。

残存する制限（初期版）:
| # | 制限 | 回避策 |
|---|---|---|
| L-1 | 前月比・目標比は「応募数」「応募単価」の2軸のみ | 他KPIの比較が必要なら calculate_kpi.py を拡張 |
| L-2 | 集計行（媒体/職種/拠点別）の応募単価目標比は常に NOT_SET | 定義が曖昧なため。明細行では算出する |
| L-3 | PPTX画像は本環境ではPillow近似（LibreOffice変換不可） | 最終体裁はPowerPoint/Googleスライドで確認 |
| L-4 | サマリー本文の生成はClaude（スクジュールは構造化JSONまで） | PowerPoint前に人が確認する運用で担保 |
| L-5 | Excel複数シートは先頭シート既定（--sheetで指定可、統合テスト未実施） | フェーズ10で追加確認 |
| L-6 | 月次のみ（週次・日次は非対応） | 将来拡張 |

## 確定済み事項（指示書で明示されたもの）

- CSV/Excelが正式対応、PDFは補助対応（転記のみ）
- 0除算は0を返さず「算出不可」
- 空欄と0を区別する
- エラー時は確定資料を作らない
- 数値計算はスクリプトで行う
- 事実/示唆/要確認の3区分
- 将来拡張機能（Drive監視・Slack通知等）は初期版に含めない
