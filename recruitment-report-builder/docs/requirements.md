# 要件定義書｜求人媒体結果報告資料 自動作成システム

- プロジェクト名: recruitment-report-builder
- 版数: 1.0（フェーズ1）
- 作成日: 2026-07-13
- 状態: ドラフト（人による確認待ち）

---

## 1. 目的

求人媒体（Indeed、求人ボックス、エンゲージ等）から出力された結果データをもとに、
KPI集計・前月比較・目標比較・分析サマリー・PowerPoint報告資料の作成を半自動化する。

- 特定企業専用ではなく、複数企業が利用できる**汎用型**とする。
- 初回利用時にClaudeが利用者へ質問し、回答から会社別設定ファイルを作成する**セルフ実装型**とする。
- 数値計算はPythonスクリプトで行い、生成AIの文章推論だけで数値を作らない。
- 最終判断は必ず人が行う設計とする。

## 2. 対象業務

| 業務 | 内容 |
|---|---|
| 月次報告 | 求人媒体の当月実績を前月・目標と比較し、報告資料を作成する |
| データ整備 | 媒体ごとに形式が異なるデータを標準形式へ統一する |
| KPI集計 | 応募単価・採用単価などのKPIを計算する |
| 課題分析 | 好調・不調の媒体や求人を整理し、改善案を提示する |
| 資料作成 | PowerPoint形式の報告資料を生成する |

## 3. 想定利用者

| 利用者 | 主な用途 | 前提スキル |
|---|---|---|
| 求人広告代理店 | 顧客への月次報告資料作成 | Excel操作程度 |
| 採用支援会社 | 支援先企業へのレポーティング | Excel操作程度 |
| 企業の採用担当者 | 社内報告・媒体評価 | Excel操作程度 |
| 営業担当者 | 提案・報告時の実績説明 | Excel操作程度 |

**AIやプログラミングに詳しくない利用者を前提とする。**
コマンドライン操作を利用者へ要求しない（スクリプト実行はClaudeが代行する）。

## 4. 入力ファイル

### 4.1 正式対応（初期版）

| 形式 | 内容 |
|---|---|
| CSV（UTF-8 / Shift_JIS） | 媒体管理画面からのエクスポートデータ |
| Excel（.xlsx） | 媒体データ、または手元で整理した表 |

入力の種類:

1. **当月データ**（必須）: 媒体×求人（職種×拠点）単位の実績
2. **前月データ**(任意): 前月比較に使用。ない場合は「新規/比較不可」扱い
3. **目標値**(任意): 目標比に使用。ない場合は「未設定」扱い
4. **企業別設定**(必須): 会社設定YAML・媒体マッピングCSV（初回設定で作成）
5. **補足コメント**(任意): 掲載変更・キャンペーン等の背景情報。サマリーの「示唆」根拠に使用可

### 4.2 補助対応

| 形式 | 扱い |
|---|---|
| PDFから転記した表データ | 利用者がCSV/Excelへ転記したものを受け付ける。PDFの自動数値抽出は正確性を保証できないため**正式対応としない**。転記データ利用時は「PDF転記のため人による数値確認必須」と警告する |

### 4.3 対応しない入力（初期版）

- PDFファイルの直接読み込み・自動抽出
- 媒体管理画面への自動ログイン・スクレイピング
- Google Drive等の自動監視
- 画像・スクリーンショット

## 5. 出力ファイル

| 出力 | 形式 | 内容 |
|---|---|---|
| 標準化済みデータ | CSV | 列名・媒体名・数値形式を統一したデータ（元データは保持） |
| KPI集計結果 | CSV | 媒体×職種×拠点別のKPI、前月比、目標比 |
| データエラー一覧 | CSV / Markdown | エラー（処理停止）と警告（続行可）を区分 |
| サマリー入力JSON | JSON | 生成AIが誤解しにくい構造化データ |
| 分析サマリー | Markdown | 全体サマリー・媒体別・職種別分析・改善提案・要確認事項 |
| PowerPoint報告資料 | .pptx | 10スライド構成の報告資料 |

すべて `output/` 配下へ日付付きファイル名で出力し、元ファイルを上書きしない。

## 6. 標準データ項目

入力データは以下の標準項目へ正規化する。

| 項目名（内部キー） | 表示名 | 型 | 必須 | 備考 |
|---|---|---|---|---|
| media | 媒体 | 文字列 | 必須 | 媒体マスタで表記揺れを統一 |
| job_category | 職種 | 文字列 | 必須 | 前後空白を削除 |
| location | 拠点 | 文字列 | 任意 | 未設定可 |
| period | 対象期間 | 年月 | 必須 | YYYY-MM に統一 |
| impressions | 表示数 | 整数 ≥0 | 任意 | |
| clicks | クリック数 | 整数 ≥0 | 任意 | |
| applications | 応募数 | 整数 ≥0 | 必須 | |
| interviews | 面接数 | 整数 ≥0 | 任意 | |
| hires | 採用数 | 整数 ≥0 | 任意 | |
| cost | 広告費 | 数値 ≥0（円） | 必須 | カンマ・円記号を除去 |
| note | 補足 | 文字列 | 任意 | |

**空欄と0の区別**: 空欄は「データなし（欠損）」、0は「実績0件」として明確に区別する。
空欄を勝手に0へ変換しない。

## 7. KPI定義

詳細は `docs/system-design.md` の「KPI定義」を正とする（フェーズ4で `references/standard-kpi.md` へ転記）。

| KPI | 計算式 | 必要項目 | 分母0件時 | 欠損時 |
|---|---|---|---|---|
| クリック率(CTR) | クリック数 ÷ 表示数 | clicks, impressions | 算出不可 | 算出不可 |
| 応募率 | 応募数 ÷ クリック数 | applications, clicks | 算出不可 | 算出不可 |
| 面接設定率 | 面接数 ÷ 応募数 | interviews, applications | 算出不可 | 算出不可 |
| 採用率 | 採用数 ÷ 応募数 | hires, applications | 算出不可 | 算出不可 |
| クリック単価(CPC) | 広告費 ÷ クリック数 | cost, clicks | 算出不可 | 算出不可 |
| 応募単価(CPA) | 広告費 ÷ 応募数 | cost, applications | 算出不可 | 算出不可 |
| 採用単価(CPH) | 広告費 ÷ 採用数 | cost, hires | 算出不可 | 算出不可 |
| 前月比 | (当月値 − 前月値) ÷ 前月値 | 当月・前月の対象値 | 前月0 → 算出不可 | 前月なし → 「新規/比較不可」 |
| 目標比 | 当月値 ÷ 目標値 | 当月値、目標値 | 目標0 → 算出不可 | 目標なし → 「未設定」 |

共通ルール:

- **0除算時は0を返さない。「算出不可（N/A）」として扱う。**
- 欠損値（空欄）を含む計算は「算出不可」とし、欠損を0とみなさない。
- 率は%表示（小数1桁）、単価は円表示（整数、四捨五入）を標準とする。
- 広告費0円かつ応募ありの場合、単価は0円と表示せず「費用0円（オーガニック等の可能性）」として警告を出す。
  ※注: 広告費0円は分子が0のケースであり0除算ではないが、誤解を招くため警告扱いとする（仮定。フェーズ2以降で確定）。

## 8. データ検証（例外処理）要件

### エラー（処理を停止し、確定資料を作らない）

- 必須列の不足（媒体・職種・応募数・広告費・期間）
- 数値列に数値以外の値（正規化後も解釈不能なもの）
- マイナス値
- 応募数より面接数が多い
- 面接数より採用数が多い
- 合計行と明細行の不一致（合計行が存在する場合）

### 警告（処理は続行するが、レポートと報告に明記）

- 前月データ不足（新規掲載扱い）
- 目標値未設定
- 未登録媒体（媒体マスタにない名前。正規化候補を提示）
- 異常値（応募単価が設定閾値超過、前月比±設定閾値超過など。閾値は会社設定で変更可）
- 重複行の疑い
- 広告費0円で応募あり
- 空欄セル

## 9. 機能要件一覧

| ID | 機能 | 概要 |
|---|---|---|
| F-01 | 初期設定（セルフ実装） | 対話形式で質問し会社別設定ファイルを作成。5〜8問ずつ質問。「不明/未設定」を許容 |
| F-02 | データ読み込み | CSV/Excelを読み込み、形式を判定 |
| F-03 | データ標準化 | 列名・媒体名・数値形式の統一。空欄と0の区別 |
| F-04 | データ検証 | エラーと警告を検出・区分。エラー時は停止 |
| F-05 | KPI計算 | 標準KPI・前月比・目標比をスクリプトで計算 |
| F-06 | サマリー生成 | 事実/示唆/要確認を区分した分析文の作成 |
| F-07 | PowerPoint生成 | 計算済みCSVの数値のみを使用して資料を生成 |
| F-08 | 最終検証 | 数値一致・レイアウト・表示の検証 |
| F-09 | 設定変更 | 既存設定の変更（媒体追加、KPI変更、スライド構成等） |
| F-10 | 検証モード | 数値検証のみ実施し、PowerPointを作らない |

## 10. 非機能要件

- **再現性**: 同じ入力から同じ計算結果が得られること。
- **透明性**: すべてのサマリー記述に根拠数値があること。計算過程をログ・中間ファイルで確認できること。
- **安全性**: 元ファイルを上書きしない。変更前にバックアップする。
- **可搬性**: パスを特定環境へ固定しない。Python 3.10以上 + 一般的なライブラリ（pandas, openpyxl, python-pptx, PyYAML）で動作。
- **秘匿性**: 個人情報（応募者氏名等）を入力に含めない運用とし、デモ・ログへ実在情報を残さない。

## 11. セキュリティ上の注意

- 入力データに応募者個人情報が含まれる場合は、利用者へ削除を依頼し、処理を続行しない（列名に「氏名」「電話」「メール」等を検出した場合に警告）。
- 会社設定ファイルには認証情報（媒体ログインID・パスワード等)を保存しない。
- 出力・ログに実在企業の機密数値を含む場合、社外共有前に人が確認する。
- デモデータはすべて架空とし、実在企業名・実在人物名を使用しない。

## 12. 人が確認する工程（必須ヒューマンチェック）

1. 初回設定完了時の設定内容の承認
2. データ検証でエラー・警告が出た際の判断
3. サマリー（分析・改善案）の内容確認 — PowerPoint作成前に必ず確認を求める
4. PowerPoint完成後の最終確認（数値・表現・体裁）
5. 初回利用時の数値照合（媒体管理画面の値との突き合わせ）

## 13. 対応範囲 / 対応しない範囲

### 対応する

- CSV/Excelの月次媒体データからの報告資料作成
- 複数媒体・複数職種・複数拠点の集計
- 前月比較・目標比較
- 表記揺れ・数値形式の正規化
- データエラー検出
- 会社別カスタマイズ（KPI・スライド構成・文体・ブランドカラー）

### 対応しない（初期版・将来拡張として分離）

- Google Drive自動監視 / ファイル追加起点の自動実行
- Slack通知・Gmail送信・定期レポート生成
- 媒体管理画面への自動ログイン
- PDFからの完全自動数値抽出
- 複数企業の一括処理
- Webダッシュボード・データベース保存
- 採用管理システム（ATS）連携
- 週次・日次レポート（初期版は月次のみ。仮定）

## 14. 完成の品質基準

- 追加情報なしで架空デモデータによるデモが可能
- 利用者自身が初期設定を完了できる
- 毎月同形式のデータで繰り返し利用できる
- 数値計算が再現可能で、根拠を確認できる
- 数値エラーを検出し、エラー時は確定資料を作らない
- 他企業へ展開でき、特定企業専用情報が埋め込まれていない
- 最終判断は人が行う
