# 分析ルール（サマリー作成時に必ず読む）

サマリーは `generate_summary_input.py` が出力した**構造化JSONの数値のみ**を根拠に作成する。
JSONにない数値・事実を記載してはならない。

## 1. 出力の3区分（必須）

すべての記述を次のいずれかに分類し、ラベルを明示する。

| 区分 | 定義 | 表現例 |
|---|---|---|
| 【事実】 | データから直接確認できる内容 | 「応募数は98件（前月比+24.1%）でした」 |
| 【示唆】 | データから合理的に考えられる可能性 | 「〜の可能性があります」「〜が影響していると考えられます」 |
| 【要確認】 | 追加情報がなければ判断できない内容 | 「〜をご確認ください」「データからは判断できません」 |

事実と示唆を同一文に混在させない。示唆には必ず根拠となる数値を括弧書き等で添える。

## 2. サマリーの構成（順序固定）

1. 全体結果 — 応募数・採用数・広告費・全体応募単価・目標達成状況
2. 前月からの変化 — 全体の増減と主な寄与
3. 好調な媒体・求人 — 判定フラグ `good` の行
4. 課題のある媒体・求人 — 判定フラグ `caution` / `priority` の行
5. 改善優先度 — priorityリストの順に番号付きで
6. 次月の推奨施策 — 各施策に根拠数値と対象を明記
7. 要確認事項 — データ警告 + 判断できなかった項目

## 3. 判定ルール（スクリプトが判定し、JSONの judgements に格納）

閾値は会社設定 `thresholds` に従う（デフォルト）:

- **好調（good)**: 応募数目標比 ≥ 100% または 応募数前月比 ≥ +20%
- **注意（caution)**: 応募単価目標比 ≥ 120% または 応募数前月比 ≤ −20%
- **改善優先（priority)**: 次の順で優先度を付ける
  1. 応募0件で広告費が発生している
  2. 応募単価が警告閾値（cpa_warning_yen）超過
  3. caution該当（応募単価悪化 > 応募数減少 の順)

Claudeが独自の閾値で判定し直してはならない。JSONの判定と異なる評価を書かない。

## 4. 禁止事項（厳守）

1. 原因を根拠なく断定しない（「〜が原因です」→ 不可。「〜の可能性があります」）
2. 求人市場の状況・季節性・競合動向を勝手に作らない（JSONのcommentsにある場合のみ言及可）
3. 不明な数値を補完しない（N/A・空欄は「算出不可」「データなし」と書く）
4. 0件を無視しない（応募0件・採用0件は必ず課題または要確認へ記載）
5. 応募数だけで媒体を評価しない（単価・率を必ず併記）
6. 採用数がない（0件・欠損）状態で費用対効果を断定しない
7. 一般論だけの改善案を提示しない（対象と根拠数値のない施策は書かない）
8. 元データに存在しない実績を記載しない
9. 事実と推測を混ぜない（区分ラベルのない記述を書かない）

## 5. 特殊ケースの記述方法

| ケース | 記述方法 |
|---|---|
| 前月比 NEW | 「新規掲載のため前月比較はできません」。増減の議論をしない |
| 目標比 NOT_SET | 「目標未設定」。達成/未達を書かず、要確認事項へ目標設定を促す |
| N/A | 「算出不可」。0と書かない |
| 広告費0円で応募あり | 単価0円と評価せず、要確認へ（無料掲載・オーガニックか確認） |
| 応募5件未満の率 | 「件数が少ないため単月では断定できません」を必ず添える |
| データ警告（validation） | 集計への影響（除外・欠損扱い等）を要確認事項に明記 |

## 6. 改善施策の書き方

- 形式: 【示唆】+ 対象（媒体/職種/拠点）+ 施策の方向性 + （根拠: 数値）
- 「検討する余地があります」「判断することが考えられます」など提案調で書く。
- 実施可否の判断は利用者に委ねる（「必ず」「すぐに」等の強制表現を使わない）。
