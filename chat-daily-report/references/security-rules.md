# security-rules.md — 個人情報・機密情報の取り扱いルール

このファイルは、日報作成時のセキュリティルールを定義します。
**このルールは常に適用され、`company-settings.md` の設定で緩めることはできません。**
(設定ファイルでは、禁止項目を「追加」することだけができます。)

---

## 1. 日報に絶対に記載しない情報(記載禁止)

チャットに含まれていても、日報には**一切記載しない**。

- パスワード、PINコード
- 認証情報(ログインID とパスワードの組、認証トークン、APIキー)
- 口座番号、クレジットカード番号
- マイナンバー、免許証番号などの公的番号

チャット内でこれらを発見した場合:

1. 日報には記載しない
2. 「Claudeによる確認結果」の「日報から除外した情報」に、**内容そのものは書かず**種類だけを記載する
   (例:「チャット内にパスワードと思われる記載があったため除外しました」)
3. チャットでパスワード等を共有しないよう、利用者へ注意を促す一文を添える

## 2. 原則として記載しない情報(業務上必要な場合を除く)

- 業務と関係のない個人の氏名
- 個人の電話番号、メールアドレス、住所
- 健康状態、家族構成などのプライベートな話題
- 個人的な予定(私用の休暇理由の詳細など)

**判断基準:** その情報がなくても日報の内容が伝わるなら、記載しない。
業務上どうしても必要な連絡先など、記載してよいか判断できない場合は、質問ルール(最大3問)の範囲で利用者へ確認する。
確認できない場合は記載せず、「要確認事項」に出力する。

## 3. 匿名化のルール

- 業務に関係のない個人が話題に出た場合は、氏名を記載せず「関係者」などに置き換える。
- 顧客名・社員名の表記は `company-settings.md` の表記設定に従う。
- 匿名化した場合は、「Claudeによる確認結果」の「日報から除外した情報」にその旨を記載する。

## 4. 利用者への注意事項(README にも記載すること)

- チャット履歴を Claude へ渡す前に、パスワードや機密情報が含まれていないか確認することを推奨します。
- 日報を Google Docs 等へ保存する際は、共有範囲(閲覧できる人)を確認してください。
- 顧客情報を含む日報の社外共有は行わないでください。
- このスキルは除外処理を行いますが、**最終確認は必ず人が行ってください。** 自動処理は完全ではありません。

## 5. Claude の動作ルール(まとめ)

1. `company-settings.md` のセキュリティ設定を読み、禁止項目の追加があれば適用する
2. 上記1〜3のルールを、設定に関係なく常に適用する
3. 出力前に、日報全体に禁止情報が含まれていないか再確認する
4. 除外・匿名化した場合は、「Claudeによる確認結果」で利用者へ報告する(内容そのものは書かない)
