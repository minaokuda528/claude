# processing-rules.md — チャット分析・日報作成の処理ルール

このファイルは、Claude がチャットを分析して日報を作成する際の判断ルールを定義します。
**利用企業はこのファイルを変更しないでください。** 企業ごとの調整は `company-settings.md` で行います。

---

## 1. 大原則(推測禁止ルール)

- **チャットに書かれていない情報を推測しない。**
- 担当者が明記されていない場合は「不明」とし、「要確認事項」に出力する。
- 期限が明記されていない場合は「不明」とし、「要確認事項」に出力する。
- 完了状況は、完了を示す記載(完了、対応済み、送信済み、共有済み など)がある場合だけ「完了」とする。
- 確定していない推測・憶測は日報に含めない。

## 2. 処理の順番

1. `company-settings.md` を読む
2. `daily-report-template.md` を読む
3. `processing-rules.md`(このファイル)を読む
4. `security-rules.md` を読む
5. 入力されたチャットを時系列に整理する
6. 重複投稿を整理する(同じ内容は1件にまとめる)
7. 雑談・対象外投稿を除外する
8. 業務内容を分類する(顧客対応/社内対応/決定事項/タスク/課題/予定)
9. 決定事項を抽出する
10. 未完了タスクを抽出する
11. 完了タスクを判定する
12. 各タスクの担当者と期限を確認する
13. 不足情報を最大3問(上限5問)質問する
14. 回答を反映する(回答がない項目は「要確認」とする)
15. テンプレートに従って日報を作成する
16. 元チャットにない情報が含まれていないか確認する
17. 機密情報・個人情報が含まれていないか確認する
18. 日報+「Claudeによる確認結果」を出力する

## 3. 抽出する項目

- 日付/担当者
- 本日の主な業務/実施内容/進捗状況
- 顧客対応/社内対応
- 決定事項/依頼事項
- 未完了タスク(担当者・期限を含む)
- 課題・懸念事項
- 明日の予定
- 確認が必要な事項

## 4. 除外する情報

- 業務と関係のない雑談
- あいさつのみの投稿
- 同じ内容の重複投稿(最新または最も情報量の多い1件を残す)
- スタンプやリアクションだけの投稿
- 確定していない推測
- 個人的な予定
- 他メンバーの勤怠・個人的な予定(不在・遅刻・私的通院など)。ただし日報作成者本人の業務進行に直接影響する場合は、健康・私的な理由を除いた事実のみを社内対応へ記載してよい
- パスワードや認証情報(security-rules.md 参照)
- 日報作成に不要な個人情報(security-rules.md 参照)

## 5. 決定事項の判定

以下の表現がある場合、決定事項の**候補**とする。

- 「決まりました」
- 「この方針で進めます」
- 「対応します」
- 「承認されました」
- 「確定しました」
- 「◯◯でお願いします」
- 「◯日実施で進めます」

**上書きルール:** その後のチャットで変更・取り消しがある場合は、**時系列で最新の内容を採用**する。
古い決定事項は日報に書かない(必要なら「変更前:◯◯ → 変更後:◯◯」と経緯を1行で書いてもよい)。

**注意:** 「〜しようと思います」「〜を検討中です」など検討段階の表現は決定事項にしない。
決定か検討か判断できない重要事項は、質問(最大3問)の対象とする。

## 6. 未完了タスクの判定

以下の表現がある場合、未完了タスクの**候補**とする。

- 「お願いします」
- 「対応してください」
- 「後で確認します」
- 「次回までに」
- 「修正します」
- 「作成します」
- 「共有します」
- 「確認が必要です」

**完了除外ルール:** 同じタスクについて、チャット内に完了報告
(「完了しました」「対応済みです」「送信済みです」「共有済みです」など)がある場合は、
未完了タスクから除外し、実施内容・進捗などの完了扱いとして記載する。

**担当者変更ルール:** タスクの担当者が途中で変更された場合は、最新の担当者を採用する。

## 7. 担当者・期限・完了状況の扱い

| 状況 | 日報への記載 |
|---|---|
| 担当者が明記されている | その担当者を記載(表記は company-settings.md に従う) |
| 担当者が明記されていない | 「不明」と記載し、要確認事項に出力(推測しない) |
| 期限が明記されている | その期限を記載 |
| 期限が明記されていない | 「不明」と記載し、要確認事項に出力(推測しない) |
| 完了を示す記載がある | 「完了」として扱う |
| 完了を示す記載がない | 「未完了(継続)」として扱う |

## 8. 不足情報の質問ルール

- 質問は**原則3問以内、最大5問**。大量の質問をしない。
- 質問するのは、日報の正確性に大きく影響する項目だけ。
- 優先順位:
  1. 完了か未完了か判断できない重要タスク
  2. 担当者が不明な重要タスク
  3. 期限が不明な重要タスク
  4. 決定事項か検討事項か判断できない内容
  5. 日報へ記載してよいか判断できない機密情報
- **回答がなくても日報は作成できること。** 回答がない項目は「要確認」として出力する。
- 軽微な不明点(重要度の低いタスクの期限など)は質問せず、「不明」として日報に記載する。

## 9. エラー・例外時の対応

| 状況 | 対応 |
|---|---|
| チャットが空・業務情報が読み取れない | 日報を作らず、入力内容の確認を利用者へ依頼する |
| 設定ファイルが読み込めない | このファイルの初期値(汎用設定)で作成し、その旨を明記する |
| チャットに複数日の内容が混在 | company-settings.md の「対象期間」に従う(初期値:最新の日付の分) |
| 日付がチャットから読み取れない | 「日付:不明(要確認)」と記載し、利用者へ確認する |

## 10. 出力前の自己確認(チェックリスト)

日報を出力する前に、以下を確認する。

- [ ] 元チャットにない情報を追加していないか
- [ ] 担当者・期限を勝手に補完していないか
- [ ] 古い決定事項を最新版で上書きしたか
- [ ] 完了済みタスクが未完了欄に残っていないか
- [ ] 雑談・重複・個人的な予定を除外したか
- [ ] パスワード・認証情報・不要な個人情報を除外したか
- [ ] テンプレートの全項目がそろっているか(該当なしは「特になし」)
- [ ] 「Claudeによる確認結果」を付けたか
