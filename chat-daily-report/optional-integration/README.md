# optional-integration — Google Docs 連携(オプション)

このフォルダは、**スキル本体とは分離したオプション**です。
Google Docs への保存を自動化したい企業向けの、参考用サンプル(Google Apps Script / GAS)と導入手順を提供します。

> **このフォルダがなくても、スキル本体は問題なく動作します。**
> 初期版のスキルは、日報を作成するところまでを担当します。
> Google Docs への保存は、まず「人が内容を確認してから手動で貼り付ける」運用を推奨します。

---

## このサンプルでできること

`google-docs-sample.gs` は、以下を行うサンプルです。

1. 日報本文を受け取る
2. Google ドキュメントを新規作成する
3. 指定したフォルダへ保存する
4. ファイル名に日付と担当者名を設定する(例:`2026-07-13_業務日報_田中`)
5. 作成した Google ドキュメントの URL を返す
6. エラーが発生した場合はログへ記録する

## 重要な注意事項(必ずお読みください)

- **Claude から GAS を直接実行する設計にはしていません。** 人が日報を確認したうえで利用してください。
- **APIキーや認証情報をコードに直接書かないでください。** Google の認証は GAS の実行ユーザー権限で行われます。
- フォルダ ID などの設定は、コード内の `CONFIG` 欄にまとめてあります。ここだけを変更してください。
- **本番利用の前に、必ずテスト用フォルダで動作を確認してください。**
- 自動送信ではなく、**最初は人が内容を確認してから保存する運用**を推奨します。

## 導入手順(非エンジニア向け)

### 手順1:GAS プロジェクトを作る

1. ブラウザで [https://script.google.com](https://script.google.com) を開きます。
2. 「新しいプロジェクト」をクリックします。
3. 表示されたエディタの中身をすべて消します。

### 手順2:サンプルコードを貼り付ける

1. 同じフォルダにある `google-docs-sample.gs` の中身をすべてコピーします。
2. GAS エディタに貼り付けます。
3. 上部のフロッピーアイコン(保存)で保存します。

### 手順3:保存先フォルダを設定する

1. Google ドライブで、日報を保存したい**テスト用フォルダ**を作ります。
2. そのフォルダを開き、URL を確認します。
   - 例:`https://drive.google.com/drive/folders/AbCdEfG12345`
   - `/folders/` の後ろの文字列(`AbCdEfG12345`)が **フォルダ ID** です。
3. コード内の `CONFIG` 欄の `FOLDER_ID` に、そのフォルダ ID を貼り付けます。

```javascript
var CONFIG = {
  FOLDER_ID: 'AbCdEfG12345',   // ← ここを自分のフォルダIDに
  FILE_NAME_PREFIX: '業務日報',
  ENABLE_LOG: true
};
```

### 手順4:テスト実行する

1. エディタ上部の関数選択で `testSaveDailyReport` を選びます。
2. 「実行」ボタンを押します。
3. 初回は Google から権限の許可を求められます。内容を確認して許可します。
4. テスト用フォルダに `2026-07-13_業務日報_テスト太郎` というドキュメントが作られれば成功です。
5. 実行ログ(下部)に、作成したドキュメントの URL が表示されます。

### 手順5:実際の日報を保存する

日報本文を渡して `saveDailyReport` を呼び出します。呼び出し方は運用に合わせて選べます。

- GAS エディタで手動実行する
- Google フォーム/スプレッドシートから呼び出す
- 社内の簡易ツールから呼び出す

いずれの場合も、**保存する前に日報の内容を人が確認**してください。

## 関数の説明

| 関数 | 役割 |
|---|---|
| `saveDailyReport(reportText, authorName, reportDate)` | 日報を Google ドキュメントとして保存し、URL を返す |
| `writeLog(message)` | ログを記録する(`CONFIG.ENABLE_LOG` が true のとき) |
| `testSaveDailyReport()` | 動作確認用のテスト関数 |

### 引数

- `reportText`(必須):日報の本文。空だとエラーになります。
- `authorName`(任意):担当者名。ファイル名に使われます。空の場合は「担当者不明」。
- `reportDate`(任意):`YYYY-MM-DD` 形式の日付。空の場合は実行日。

## うまくいかないとき

| 症状 | 対処 |
|---|---|
| 「CONFIG.FOLDER_ID が未設定です」 | 手順3のフォルダ ID 設定を確認する |
| 「日報本文が空です」 | `reportText` に日報のテキストを渡しているか確認する |
| 権限エラーが出る | 実行時に表示される権限の許可を行う。テスト用フォルダへのアクセス権を確認する |
| フォルダが見つからない | フォルダ ID が正しいか、そのフォルダにアクセスできるアカウントで実行しているか確認する |

## セキュリティ上の注意

- 保存先フォルダの**共有範囲(閲覧できる人)**を必ず確認してください。
- 顧客情報や機密情報を含む日報は、共有範囲を限定したフォルダに保存してください。
- ログに日報本文そのものは記録していません(ファイル名と URL のみ)。運用に合わせて調整してください。
