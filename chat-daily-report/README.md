# chat-daily-report — チャットから業務日報を作成する Claude スキル

社内チャットの履歴を Claude に渡すと、その日の業務内容・決定事項・未完了タスク・課題・翌日の予定を整理し、
Google Docs へ貼り付けられる業務日報を自動で作成するスキルです。

このマニュアルは、**プログラミングの知識がない方でも、読むだけで導入・設定・利用できる**ことを目指しています。

## 1. このスキルでできること

- チャット履歴を読み込み、業務日報(Markdown形式)を自動で作成します。
- 以下を自動で整理します。
  - 本日の主な業務、実施内容・進捗
  - 顧客対応・社内対応
  - 決定事項(途中で変更された場合は最新の内容を採用)
  - 未完了・継続タスク(担当者・期限つき)
  - 課題・懸念事項、明日の予定
- 雑談・あいさつ・重複投稿・スタンプのみの投稿を自動で除外します。
- パスワードや不要な個人情報を日報に含めません。
- **チャットに書かれていないことは推測しません。** 担当者や期限が不明な場合は「不明」と記載し、「要確認事項」に出します。
- 会社ごとの調整は、設定ファイル1つ(`references/company-settings.md`)を書き換えるだけで行えます。

## 2. このスキルだけではできないこと

以下は初期版では行いません(別途の作業やオプション導入が必要です)。

- チャットツール(Slack / Chatwork / Teams など)からの履歴の**自動取得**
  → 手動でコピー&ペースト、またはテキストファイルの添付が必要です。
- Google Docs への**自動保存**
  → 手動で貼り付けます(自動化したい場合は `optional-integration/` を参照)。
- 週報・月報など、日報以外の帳票の作成
- 複数人分の日報の一括作成
- メール・カレンダーなど、チャット以外からの情報抽出
- 書かれていない情報の補完(仕様として推測しません)

## 3. 導入手順

1. このフォルダ(`chat-daily-report` 一式)を用意します。
2. Claude(claude.ai など)を開きます。
3. スキル一式を Claude に登録(またはファイルをアップロード)します。
   - 最低限、`SKILL.md` と `references/` 内のファイルが読み込まれる状態にします。
4. `references/company-settings.md` を開き、自社の情報を入力します(→ [4章](#4-設定ファイルの編集方法))。
5. まずはデモデータで動作を確認します(→ [5章](#5-デモデータでの試し方))。
6. 問題なければ、実際のチャットで利用します(→ [6章](#6-実際のチャットを使う方法))。

> **ヒント:** 最初は設定を変えず、デモデータ([5章](#5-デモデータでの試し方))で一度動かしてみることをおすすめします。

## 4. 設定ファイルの編集方法

**編集するのは原則 `references/company-settings.md` の1ファイルだけです。**

1. `references/company-settings.md` をテキストエディタで開きます。
2. 各項目の「:」の右側を、自社の内容に書き換えます。
3. 分からない項目は空欄のままにします(初期値が使われます)。
4. 保存して、スキルを再登録(またはファイルを再アップロード)します。

### 最初に変更するとよい項目

| 項目 | 例 |
|---|---|
| 会社名 | 株式会社◯◯ |
| 部署名 | 営業部 |
| 日報作成者名 | 田中(空欄ならチャットから読み取り、不明なら「不明」) |
| 顧客名の表記方法 | 「◯◯様」/ イニシャル表記 など |
| 文体 | です・ます調 / である調 |

その他の項目(社内用語・略語・記載禁止情報の追加など)は、`references/customization-guide.md` に具体例があります。

> **注意:** `processing-rules.md`(処理ルール)と `security-rules.md`(セキュリティルール)は編集しないでください。
> これらは全社共通の判断ルールで、企業ごとの調整は `company-settings.md` で行う設計です。

## 5. デモデータでの試し方

実データの前に、付属の架空データで動作を確認できます。

1. `assets/demo-chat.txt` の中身をすべてコピーします。
2. Claude に貼り付け、次のように依頼します。

   ```text
   添付したチャット履歴をもとに、本日の業務日報を作成してください。
   company-settings.md の設定と、daily-report-template.md の形式に従ってください。
   ```

3. 出力された日報を、`assets/demo-daily-report.md`(正解例)と見比べます。
4. 雑談が除外され、担当者不明・期限不明が「要確認事項」に出ていれば、正しく動作しています。

## 6. 実際のチャットを使う方法

1. その日のチャット(1日分)を、チャットツールからコピーします。
2. **渡す前に、パスワードや機密情報が含まれていないか確認します**(→ [11章](#11-セキュリティ上の注意))。
3. Claude に貼り付け、[7章](#7-日報を作成する指示例)の指示例で日報作成を依頼します。
4. Claude が重要な不足情報だけを最大3問質問します。回答するか、「回答をスキップして作成して」と伝えます。
5. 出力された日報を確認し、Google Docs へ貼り付けます(→ [12章](#12-google-docs-へ貼り付ける方法))。

> 複数日のチャットが混ざっている場合は、初期設定では最新の日付の分が対象になります。

## 7. 日報を作成する指示例

以下をそのままコピーして使えます。

```text
添付したチャット履歴をもとに、本日の業務日報を作成してください。

company-settings.md の設定と、
daily-report-template.md の形式に従ってください。

不足している重要情報がある場合は、
日報を作成する前に最大3問まで質問してください。

チャットに記載されていない内容は推測しないでください。
```

## 8. 出力結果の確認方法

日報の末尾には、必ず「**Claudeによる確認結果**」が付きます。ここを最初に確認してください。

- **推測して追加した情報:** 「なし」であることを確認します(「なし」以外なら、その部分は削除を検討)。
- **要確認事項:** 担当者不明・期限不明など、あなたが補う必要がある項目です。
- **日報から除外した情報:** 個人情報やパスワードなど、除外された情報の種類が分かります。
- **情報不足により記載できなかった項目:** 追記が必要な項目です。

そのうえで、本文に事実と違う記載がないか、**必ず人の目で最終確認**してください。

## 9. よくあるエラー

| 症状 | 原因 | 対処 |
|---|---|---|
| 「業務情報が読み取れません」と言われる | チャットが空、または雑談のみ | 業務に関する発言を含むチャットを渡す |
| 日付が「不明」になる | チャットに日付の記載がない | 指示に「本日の日付は◯月◯日です」と補足する |
| 設定が反映されない | 設定ファイルが読み込まれていない | `company-settings.md` を再アップロードして依頼し直す |
| 質問が多すぎる/少なすぎる | 重要度の判断が文脈依存 | 「質問は◯問まで」と指定する。回答不要なら「要確認のままで作成して」 |
| 担当者や期限が「不明」ばかり | チャットに明記されていない | 仕様どおりの動作。要確認事項を見て手動で補う |
| 発言者が特定できない | チャットの形式が崩れている | 「発言者:内容」の形に整えてから渡す |

## 10. カスタマイズ方法

`references/customization-guide.md` に詳しい手順があります。代表的な例:

- **文体を変える:** `company-settings.md` の「文体」を `である調(常体)` に変更。
- **顧客名をイニシャルにする:** 「顧客名の表記方法」を `イニシャル表記(例:A社様)` に変更。
- **社内用語・略語を登録する:** 「社内用語」「略語」に `用語=意味` の形で記入。
- **不要な項目を消す:** 「日報に含めない項目」に項目名(例:顧客対応)を記入。
- **日報の見出し構成を大きく変える:** `references/daily-report-template.md` を編集(上級者向け)。

## 11. セキュリティ上の注意

- チャット履歴を Claude へ渡す前に、**パスワード・認証情報・機密情報が含まれていないか確認**してください。
- このスキルはパスワードや不要な個人情報を自動で除外しますが、**自動処理は完全ではありません。最終確認は必ず人が行ってください。**
- 日報を Google Docs 等へ保存する際は、**共有範囲(閲覧できる人)**を必ず確認してください。
- 顧客情報を含む日報を社外へ共有しないでください。
- パスワードなどをチャットで共有する運用自体を避けることをおすすめします。
- 詳細は `references/security-rules.md` を参照してください。

## 12. Google Docs へ貼り付ける方法

初期版では手動で貼り付けます。

1. 出力された日報(「業務日報」から始まる部分)をコピーします。
2. Google ドキュメントを新規作成します。
3. 貼り付けます。Markdown の見出し(`#`)や表がそのまま構造として反映されます。
   - うまく反映されない場合は、「編集」→「貼り付け」時に「書式なしテキストとして貼り付け」を試すか、
     Google ドキュメントの「Markdown を自動検出」設定を有効にしてください。
4. 「Claudeによる確認結果」の部分は、社内共有時に残すか削除するか、運用に合わせて判断してください。

> Google Docs への保存を自動化したい場合は、`optional-integration/`(フェーズ6で提供予定)のサンプルを参照してください。
> ただし、まずは人が確認してから保存する運用を推奨します。

## 13. サポートが必要になるケース

以下は、設定ファイルの編集だけでは対応できず、開発・追加作業が必要です。

- チャットツールからの履歴の自動取得を実装したい
- Google Docs への自動保存を導入したい(`optional-integration/` の応用)
- 週報・月報など、日報以外の帳票を作りたい
- 複数人分の日報を一括で作りたい
- 日報の項目を大幅に作り替えたい(テンプレートの大規模改修)
- 出力が期待と大きく異なり、設定の見直しでも解決しない
