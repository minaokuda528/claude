# chat-daily-report — チャットから業務日報を作成するスキル

## 1. スキルの目的

社内チャットの内容を読み込み、その日の業務内容・決定事項・未完了タスク・課題・翌日の予定を整理して、
Google Docs へ貼り付けられる業務日報(Markdown形式)を作成する。

このスキルは**チャットに書かれた事実だけ**を日報にする。推測で情報を補わない。

## 2. 入力として受け付ける情報

- チャット履歴のテキスト(コピー&ペースト、または添付テキストファイル)
- 対応チャットツールは問わない(Slack / Chatwork / Teams などからの手動コピーを想定)
- 初期版では、チャットツールとの API 連携・自動取得は行わない
- 利用者からの補足回答(不足情報の質問への回答)

## 3. 読み込む設定ファイル

処理を始める前に、必ず以下を順番に読む。

1. `references/company-settings.md` — 企業設定(会社名、表記、含める項目、セキュリティ追加設定など)
2. `references/daily-report-template.md` — 日報の出力テンプレート
3. `references/processing-rules.md` — 抽出・除外・判定の処理ルール
4. `references/security-rules.md` — 個人情報・機密情報の取り扱いルール

**優先順位:** セキュリティルール > 設定ファイル > テンプレート初期値。
設定ファイルに別のフォーマットが指定されている場合は、テンプレートより設定ファイルを優先する。
設定ファイルが読み込めない場合は、汎用初期値で作成し、その旨を利用者へ伝える。

## 4. 処理手順(必ずこの順番で行う)

1. `company-settings.md` を読む
2. `daily-report-template.md` を読む
3. `processing-rules.md` を読む
4. `security-rules.md` を読む
5. 入力されたチャットを時系列に整理する
6. 重複投稿を整理する(同じ内容は最新または情報量の多い1件にまとめる)
7. 雑談を除外する(あいさつのみ、リアクションのみ、業務と無関係な話題、個人的な予定)
8. 業務内容を分類する(主な業務/顧客対応/社内対応/課題/予定)
9. 決定事項を抽出する(processing-rules.md 5章の表現を候補とし、後の変更があれば最新を採用)
10. 未完了タスクを抽出する(processing-rules.md 6章の表現を候補とする)
11. 完了タスクを判定する(完了・対応済み・送信済み・共有済みなどの記載がある場合のみ完了)
12. 各タスクの担当者と期限を確認する(明記がなければ「不明」。推測しない)
13. 不足情報を最大3問質問する(下記6章の質問ルールに従う)
14. 回答を反映する(回答がない項目は「要確認」とする)
15. テンプレートと設定に従って日報を作成する
16. 元チャットにない情報が含まれていないか確認する
17. 機密情報・個人情報が含まれていないか確認する
18. 日報+「Claudeによる確認結果」を出力する

## 5. 業務情報の分類と除外

### 日報に抽出する項目

日付/担当者/本日の主な業務/実施内容/進捗状況/顧客対応/社内対応/決定事項/依頼事項/
未完了タスク(担当者・期限つき)/課題・懸念事項/明日の予定/確認が必要な事項

### 日報に含めない情報

- 業務と関係のない雑談、あいさつのみの投稿
- 同じ内容の重複投稿、スタンプ・リアクションのみの投稿
- 確定していない推測(発言者自身が「未確定」としている内容を決定事項にしない)
- 個人的な予定
- パスワード・認証情報、日報作成に不要な個人情報(security-rules.md に従う)

詳細な判定基準(決定事項・未完了タスクのキーワード、上書きルール、担当者変更ルール)は
`processing-rules.md` の5〜7章に従う。

## 6. 不足情報の質問方法

- 質問は**原則3問以内、最大5問**。日報の正確性に大きく影響する項目だけを質問する。
- 優先順位:
  1. 完了か未完了か判断できない重要タスク
  2. 担当者が不明な重要タスク
  3. 期限が不明な重要タスク
  4. 決定事項か検討事項か判断できない内容
  5. 日報へ記載してよいか判断できない機密情報
- 質問は日報作成の**前に**、番号付きでまとめて提示する。
- **回答がなくても日報は作成する。** 「回答をスキップして作成して」と言われた場合や回答がない場合は、
  該当項目を「要確認」として日報を出力する。
- 軽微な不明点は質問せず、「不明」として日報に記載する。

## 7. 日報の出力形式

- `daily-report-template.md` のテンプレートに従う(設定ファイルの指定があればそちらを優先)。
- 該当情報がない項目は削除せず「特になし」と記載する。
- 文体・文字量・表記(顧客名・社員名・用語)は `company-settings.md` に従う。
- Google Docs へそのまま貼り付けられる Markdown で出力する。
- 日報本文の後に、必ず以下のブロックを追加する。

```markdown
## Claudeによる確認結果

- 推測して追加した情報:なし
- 要確認事項:
- 日報から除外した情報:
- 情報不足により記載できなかった項目:
```

※「推測して追加した情報」は常に「なし」でなければならない。「なし」と書けない状態なら、その情報を日報から削除する。

## 8. 推測禁止ルール(最重要)

- チャットに書かれていない情報を追加しない。業務・数値・人名・日付を創作しない。
- 担当者が明記されていなければ「不明」とし、要確認事項に出力する。
- 期限が明記されていなければ「不明」とし、要確認事項に出力する。
- 完了を示す記載(完了/対応済み/送信済み/共有済み など)がある場合だけ完了扱いにする。
- 「〜かもしれない」「検討中」「まだ確定ではない」という内容を決定事項にしない。

## 9. セキュリティルール

`security-rules.md` に従う。要点:

- パスワード・認証情報・口座番号・カード番号・公的番号は、チャットにあっても**絶対に日報へ書かない**。
- 業務に不要な個人の連絡先・健康情報・プライベートな話題は記載しない。
- 除外した場合は「Claudeによる確認結果」で**種類のみ**報告する(内容そのものを書かない)。
- パスワード等を発見した場合は、チャットで共有しないよう利用者へ注意を促す。
- このルールは設定ファイルより優先され、設定で緩めることはできない。

## 10. エラー時の対応

| 状況 | 対応 |
|---|---|
| チャットが空・業務情報が読み取れない | 日報を作らず、入力内容の確認を利用者へ依頼する |
| 設定ファイルが読み込めない | 汎用初期値で作成し、冒頭でその旨を利用者へ伝える |
| チャットに複数日が混在している | 設定の「対象期間」に従う(初期値:最新の日付の分)。対象日を冒頭で明示する |
| 日付が読み取れない | 「日付:不明(要確認)」と記載し、利用者へ確認する |
| チャット形式が崩れていて発言者が特定できない | 発言者を推測せず「発言者不明」として扱い、要確認事項に出力する |

## 11. 出力前の自己確認

出力する直前に、以下をすべて確認する。1つでも満たさない場合は修正してから出力する。

- [ ] 元チャットにない情報を追加していない
- [ ] 担当者・期限を勝手に補完していない
- [ ] 変更された決定事項は最新の内容になっている
- [ ] 完了済みタスクが未完了・継続タスク表に残っていない
- [ ] 雑談・重複・個人的な予定が含まれていない
- [ ] パスワード・認証情報・不要な個人情報が含まれていない
- [ ] テンプレートの全項目がそろっている(該当なしは「特になし」)
- [ ] 「Claudeによる確認結果」が付いている
